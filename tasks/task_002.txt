## 1. Set up PostgreSQL Docker container and connection configuration [pending]
### Dependencies: None
### Description: Create Docker configuration for PostgreSQL, configure connection settings in the application, and implement connection pooling with proper environment variable management.
### Details:
1. Create a Docker configuration for PostgreSQL in `docker-compose.yml`:
   - Use the official PostgreSQL image (postgres:14-alpine for smaller size)
   - Configure environment variables (POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB)
   - Set up volume mapping for data persistence (`./pgdata:/var/lib/postgresql/data`)
   - Expose the standard port (5432) with proper network configuration

2. Install the AdonisJS Lucid provider: `npm i @adonisjs/lucid`

3. Configure the PostgreSQL connection in `config/database.ts`:
   - Set up environment variables in `.env` file (DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME)
   - Implement connection pooling with appropriate settings (min: 2, max: 20)
   - Add SSL configuration for production environments
   - Configure query timeout and reconnection strategies

4. Create a database initialization script in `docker-entrypoint-initdb.d/` to ensure database and extensions are created on container startup

5. Test the connection with a health check endpoint in the application

Testing approach:
- Verify container starts successfully with `docker-compose up postgres`
- Test connection from application with `node ace db:ping`
- Implement and run a simple query test to validate connection settings

## 2. Create PostgreSQL migrations and models with relationships [pending]
### Dependencies: 2.1
### Description: Design and implement database schema migrations for all required tables with proper relationships, constraints, and indexes.
### Details:
1. Create database migrations for all required tables using AdonisJS migration system:
   - Users table: `node ace make:migration users`
     - Include columns: id, email, password_hash, name, role, created_at, updated_at
     - Add appropriate indexes on email and role fields
   - Email metadata table: `node ace make:migration email_metadata`
     - Include columns: id, user_id (foreign key), subject, sender, recipients, date, content_preview, created_at, updated_at
     - Add indexes on user_id, date, and sender
   - Processing records table: `node ace make:migration processing_records`
     - Track processing status of emails
   - Notifications table: `node ace make:migration notifications`
   - User settings table: `node ace make:migration user_settings`
   - Email threads table: `node ace make:migration email_threads`
   - Classification rules table: `node ace make:migration classification_rules`

2. Implement models with relationships using Lucid ORM:
   - Create User model with relationships to emails, settings, etc.
   - Create EmailMetadata model with relationship to User
   - Create remaining models with proper relationships
   - Implement relationship methods (hasMany, belongsTo, etc.)

3. Set up database seeders for testing:
   - Create seeders for each table with realistic test data
   - Implement a master seeder that runs all seeders in the correct order

4. Run migrations with `node ace migration:run`

Testing approach:
- Verify migrations apply successfully
- Test model relationships with simple queries
- Run seeders and validate data integrity
